# MANAGEMENT — איך מנהלים את הפרויקט

## ענפים

| ענף | אחראי על | מה מותר לשנות |
|---|---|---|
| `main` | מה שמפורסם באתר | רק מיזוג של ענף שעבר בדיקות, ושינויים במבנה הנתונים ([schema.md](schema.md)) |
| `feature/content` | הספרים | `scripts/`, `public/data/` |
| `feature/ui` | המסך | `src/`, `index.html` |
| `feature/quality` | תיעוד, טסטים והערכה | `docs/`, `tests/`, `scripts/eval-data.mjs`, `.github/` |
| `feature/chat-server`, `feature/chat-ui` | ניסוי הצ'אט | לא ממוזגים כרגע ([PLAN.md](PLAN.md), שלב 3) |

**כלל אצבע:** שני ענפים לא נוגעים באותם קבצים, ולכן אפשר לעבוד עליהם במקביל.
שינוי במבנה הנתונים נעשה קודם ב-`main` וב-[schema.md](schema.md), ורק אז בענפים.

## איך מכניסים שינוי

1. עוברים לענף המתאים ומעדכנים אותו מ-`main`.
2. עושים את השינוי.
3. מריצים בדיקות:
   ```bash
   npm test
   npm run eval
   npm run build
   ```
4. בודקים בעין עם `npm run dev`, במחשב ובטלפון.
5. ממזגים ל-`main` ודוחפים. GitHub Actions מריץ שוב טסטים והערכה, ורק אם הם עוברים מפרסם את האתר.

## עדכון ספר מהמקור

```bash
npm run fetch-books   # מוריד ובונה מחדש את שני הספרים
npm run eval          # חייב לעבור לפני שמכניסים את הקבצים
```
אם ההערכה נכשלת אחרי עדכון, המקור כנראה שינה מבנה. לא מכניסים את הקבצים עד שמתקנים את המפרק.

- כל דחיפה ל-`main` מפרסמת אוטומטית ל-https://revitalbm01-glitch.github.io/sifrei-halacha/ ([deploy.yml](../.github/workflows/deploy.yml)).

## מעקב משימות

- **לוח העבודה:** [תוכנית עבודה — ספרי הלכה](https://github.com/users/revitalbm01-glitch/projects/1). עמודות: לביצוע ← בעבודה ← בוצע.
- **משימות:** כל משימה היא Issue בריפו, משויכת לשלב (Milestone) ולתווית (`chat`, `ui`, `decision`...).
- **שלבים:** [שלב 2 — שיפורי קריאה](https://github.com/revitalbm01-glitch/sifrei-halacha/milestone/2), [שלב 3 — צ'אט](https://github.com/revitalbm01-glitch/sifrei-halacha/milestone/1). התמונה המלאה ב-[PLAN.md](PLAN.md).

**מחזור חיים של משימה:**
1. משימה חדשה: Issue עם תיאור, "גמור כש", שלב ותווית. מוסיפים אותה ללוח, והיא נכנסת ל"לביצוע".
2. מתחילים לעבוד: גוררים בלוח ל"בעבודה", ופותחים ענף, למשל `issue-12-read-marks`.
3. מסיימים: בהודעת השינוי כותבים `Closes #12`. כשהשינוי נכנס ל-`main` ה-Issue נסגר, ומעבירים אותו ל"בוצע".
